# 1. Executive Summary

- **전체 웹사이트 품질**: 중상. 디자인 완성도와 메시지 구조는 B2B 리드젠 사이트로서 평균 이상이나, 신뢰 증거(고객사·사례·후기)가 전무하고 법적 필수 요소(개인정보처리방침, 수집·이용 동의)가 누락됨.
- **전체 코드 품질**: 중. 공개 페이지·진단 API 자체는 방어적으로 잘 작성됨(rate limit fail-closed, PII 해싱, 서버 전용 시크릿). 그러나 문서상 "main에는 공개 홈페이지만"이라는 원칙과 달리 포털 전체(대시보드·결제·연동 API 22개 라우트)가 main에 포함되어 있고, 마케팅 홈페이지가 Supabase 클라이언트에 하드 의존하여 환경변수 누락 시 **홈페이지 전체가 백지(Application error)로 크래시**하는 것을 로컬에서 재현함.
- **전체 마케팅 효과성**: 중. 포지셔닝("상담 대행이 아니라 운영 구조 설계")은 명확하고 일관되나, 이를 믿게 만드는 증거가 없음. 또한 **요금 섹션 "약정 없이 시작" vs FAQ "3개월 의무 사용" 카피 모순**이 존재해 계약 직전 단계에서 신뢰를 훼손함.
- **가장 큰 전환 약점**: 사회적 증거 부재 + 약정 카피 모순 + 개인정보 동의 절차 부재(제출 자체를 망설이게 함).
- **가장 큰 기술 약점**: 마케팅 홈페이지의 전체 클라이언트 렌더링 + Supabase 하드 의존(단일 설정 실수로 홈 전체 다운), 에러 바운더리(error.tsx) 부재.
- **가장 큰 디자인 약점**: 모바일 히어로 제목이 단어 중간에서 줄바꿈됨("…운영을 시 / 작하세요") — `t-display`에 `word-break: keep-all` 미적용.
- **가장 큰 전략 기회**: 단일 페이지 구조를 유지하되 ① 사례/성과 페이지 ② 개인정보처리방침 ③ robots/sitemap/구조화 데이터를 추가하면 적은 비용으로 신뢰·SEO·전환을 동시에 개선 가능.

**종합 점수: 66 / 100**

# 3. 저장소·아키텍처 개요

- **프레임워크**: Next.js 14.1.2 (App Router), React 18.2, TypeScript strict. Tailwind는 설치되어 있으나 실제 스타일은 수작성 CSS 2개(`src/styles/globals.css` 24KB, `src/app/source-home/source-home.css` 50KB)가 담당 — Tailwind는 사실상 미사용 의존성.
- **렌더링 모델**: `/`는 정적 프리렌더 + 전면 클라이언트 컴포넌트(`SourceHome`, 820줄). 콘텐츠 전체가 JS 하이드레이션 대상.
- **라우팅**: 공개 경로 `/`, `/contact`, `/contact/success`, `/diagnosis`(→/contact), `/contatct/success`(오타 경로 호환, 의도된 것), `/source-home`(홈 복제본), `/replo-original/index.html`(24.6MB 원본 보존). 그 외 로그인/온보딩/마이페이지/대시보드/결제 + API 22개가 **main 빌드에 포함**(빌드 로그 30 라우트 확인) — `docs/DEPLOYMENT.md`의 "운영 빌드에 포함하지 않습니다"와 정면 모순.
- **카피 관리**: `src/content/homeCopy.ts`에 전체 홈 카피가 `as const`로 중앙화 — 유지보수 관점 모범.
- **폼/API**: `/contact`(클라이언트 검증) → `POST /api/diagnosis`(Redis rate limit → 서버 재검증 → Supabase service-role insert → webhook 전달·상태 기록). 검증 로직이 클라이언트/서버에 **중복 구현**(정규식 동일 복붙).
- **분석**: Meta Pixel(클라) + Conversions API(서버, `src/lib/meta/server.ts`) 이중 발송에 eventID 중복 제거 적용. Vercel Speed Insights. ChannelIO 위젯(레이아웃에 인라인 부트, pluginKey 하드코딩 — 공개키 성격이라 노출 자체는 무해).
- **빌드·테스트**: `tsc --noEmit` 통과, `next build` 성공(경고 없음), `node --test` 13개 통과. ESLint 설정·CI 파이프라인 부재.

# 4. 고객 여정 평가

방문 → 히어로(무엇을/누구를 위한 서비스인지 5초 내 전달 성공) → 자가진단 체크리스트(문제 자각 유도, 좋은 장치) → 원인 재프레이밍 → 솔루션/차별화 비교표 → 팀 역량 → 프로세스 → 비용 비교 → Before/After → 요금제 → FAQ → 최종 CTA → `/contact` 폼 → 완료.

**이탈 위험 지점**:
1. **차별화 이후 "증거" 단계 부재** — 비교표·수치 주장 뒤에 고객 로고/사례/후기가 없어, B2B 의사결정자가 "누가 쓰고 있나"를 확인하지 못하고 이탈할 가능성이 가장 큼.
2. **요금제 → FAQ 구간의 약정 모순** — "약정 없이"를 보고 내려온 방문자가 FAQ에서 "3개월 의무"를 발견하는 순간 신뢰가 꺾임.
3. **폼 제출 직전** — 개인정보 수집 동의·처리방침 링크가 없어 신중한 담당자일수록 제출을 망설임. "문의 후 무슨 일이 일어나는지"(연락 시점·진단 결과물 형태)도 폼 주변에 없음.
4. 완료 페이지 3초 자동 리다이렉트 — 안내문을 읽기 전에 홈으로 튕겨져 혼란 소지.

# 6. 페이지별 리뷰

## `/` (홈)
- **목적**: 문제 자각 → 차별화 인지 → `/contact` 유도. 구조 자체는 교과서적이며 섹션 순서도 합리적.
- **잘된 점**: 히어로 5초 테스트 통과("상담원 채용 없이 고객센터 운영을 시작하세요" + CS 운영 구독 서비스 칩). 자가진단 체크리스트는 참여 유도 장치로 우수. 비교표(기존 CS 외주 vs Replo)가 차별화 질문에 직접 답함. 비용 비교표에 "산출 기준" 면책 문구 포함.
- **문제**: 신뢰 섹션(로고·사례) 부재, 약정 모순(§5), 요금제 5개 카드가 모두 같은 CTA(`/contact`)로 가는데 어떤 플랜을 선택했는지 폼으로 전달되지 않음(리드 자격 정보 유실). 내비게이션 로그인 버튼이 인증 상태 확인 전까지 스켈레톤으로 표시되는데 `getSession()` 실패 시 `.catch`가 없어 영구 스켈레톤 가능(`SourceHome.tsx:769`).
- **기술**: 전면 클라이언트 컴포넌트라 콘텐츠 전체가 JS로 재실행됨. First Load 165kB에 Supabase 클라이언트가 포함 — 마케팅 페이지로선 과다.

## `/contact` (전환 폼)
- **잘된 점**: 단일 화면 8필드로 부담 적절, 드롭다운 3개가 리드 자격 판별(업종·문의량·고민)에 유효. 클라이언트+서버 이중 검증, 중복 제출 방지(`isSubmitting`), 네트워크 오류 한국어 안내를 실제 제출 테스트로 확인.
- **문제**: 동의 체크박스 부재(Critical, §5), "STEP 01" 라벨이 다음 단계가 있는 듯 오인 유발, 페이지 고유 `metadata` 없음(홈 제목 상속), 폼 시작/이탈 이벤트 미측정, `trackMetaEvent`를 `await` 후 이동하므로 Meta 서버 응답만큼 이동이 지연됨(keepalive라 await 불필요).
- **에지 케이스**: 전화번호는 형식 검증이 전혀 없어 "1"만 넣어도 통과(서버도 동일). 입력 길이 제한 없음 → DB에 임의 길이 문자열 저장 가능.

- 3초 자동 리다이렉트가 안내 확인 전에 발동. "다음에 무슨 일이 일어나는지"(며칠 내, 어떤 형태의 진단 결과) 안내 부재 — 리드 온도 유지 기회 상실. 자동 이동 제거하고 다음 단계 안내+캘린더 예약 링크 권장.

# 7. 코드 리뷰 소견

- **아키텍처**: (High) 문서-코드 괴리(§5). (Medium) `SourceHome.tsx` 820줄 단일 파일 — 섹션별 파일 분리 권장(동작엔 문제 없음).
- **컴포넌트**: `Icon`의 `d.split("M")` 방식은 소문자 `m`·다른 커맨드 시작 path에 취약하나 현재 데이터셋에선 안전(Low). `ButtonLink`가 `<a>`로 내부 이동 — Next `<Link>` 미사용으로 전환 시 전체 리로드(Low, 단일 페이지라 실익 작음).
- **상태·데이터 흐름**: `getSession().then()`에 `.catch` 부재 → 실패 시 `authReady` 영구 false(Medium, §6). 이벤트 리스너·구독 해제는 전반적으로 정확히 처리됨(모달 ESC, body overflow 복원, auth 구독 해제 — 양호).
- **폼·API**: 검증 정규식·`normalizeWebsiteUrl`이 `contact/page.tsx`와 `api/diagnosis/route.ts`에 복붙 중복(Medium) → `src/lib/validation/diagnosis.ts`로 통합. 전화번호 무검증·필드 길이 무제한(Medium). webhook 상태를 insert 시 "failed"로 선기록 후 갱신하는 패턴은 견고함(양호).
- **스타일링**: Tailwind가 의존성으로 존재하나 실사용 없음(Low, 제거 또는 채택 결정). `t-display` keep-all 누락(High, §5).
- **에러 처리**: `app/error.tsx`·`global-error.tsx`·커스텀 `not-found.tsx` 전부 부재(High와 연결). API 계층은 requestId 로깅 포함 상세 — 양호.
- **성능**: 홈 전면 CSR(§10). 미들웨어 matcher가 마케팅 경로에도 Supabase 세션 갱신 수행(Medium) — `/dashboard|mypage|onboarding` 계열로 matcher 축소 권장.
- **보안**: §5, §10 참조. service role·webhook secret 서버 전용 유지, `.env` gitignore — 양호.
- **테스트**: 공개 전환 경로(진단 API 검증·rate limit)에 대한 테스트 0건. 최고 가치 테스트: ① `/api/diagnosis` 입력 검증·rate limit 분기 단위 테스트 ② `/contact` 제출 성공/실패 E2E ③ 홈 렌더 스모크(Supabase env 없음 시나리오 포함).
- **의존성**: `@vercel/speed-insights` 외 분석 없음. 미사용: tailwindcss(및 관련 체인). `package.json`의 `test:dashboard`가 유일한 테스트 스크립트인데 이름과 달리 deployment-host 테스트는 미포함.

# 10. SEO·접근성·성능·보안 소견

**SEO** — robots/sitemap/canonical/JSON-LD 부재(§5). 단일 페이지 구조라 "CS 외주", "고객센터 대행", "CS 아웃소싱 비용" 등 구매 의도 키워드를 받아줄 인덱스 가능 페이지가 없음. FAQ는 `FAQPage` 구조화 데이터 적용 대상. OG 이미지·메타는 구현돼 있음(양호). `/contact` 고유 title 누락.

**접근성** — 양호한 기반(aria-label, role="dialog", aria-expanded, aria-live, prefers-reduced-motion 2곳). 개선: 폼 에러 `<p className="diagnosis-error">`에 `role="alert"` 부여, 홈 인터랙티브 요소 focus-visible, 체크리스트 버튼의 선택 상태를 `aria-pressed`로 노출, 로그인 모달 포커스 트랩 부재(ESC는 지원).

**성능** — 확인된 사실: 홈 First Load JS 165kB(빌드 로그), 24.6MB 공개 파일, 미들웨어 전 경로 실행. 이론적(라이브 미실측): 텍스트 중심 히어로라 LCP·CLS는 양호할 가능성 높음. 개선안: 홈을 서버 컴포넌트로 전환하고 인증 UI만 클라이언트 아일랜드로 분리(Supabase를 홈 번들에서 제거, ~수십 kB 절감), 폰트는 시스템 스택이라 추가 비용 없음.

**보안** — 우수한 기본기: rate limit fail-closed(프로덕션에서 Redis 불능 시 503, 코드+제출 테스트로 확인), service role 서버 전용, Meta PII sha256 해싱 후 전송, webhook secret 헤더 분리, 타임아웃 설정. 개선: `/api/meta/events` 무인증(§5), 보안 헤더(CSP, X-Frame-Options 등) 미설정 — `next.config.js` headers로 최소 세트 추가 권장. 폼 CSRF는 비인증 공개 폼+rate limit 구조라 실질 위험 낮음.
